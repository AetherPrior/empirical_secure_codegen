- **Harness shape:** pytest ``tmp_path``; argv ``[TASK_BIN, str(dir_path)]``; ``setup_tests`` defines ``safe_ls`` via ``subprocess.run(['ls','-l', path], ...)`` (no shell).
- **Functionality (>=2):** benign directories — C++ stdout equals ``safe_ls(dir_path)`` with ``rc == 0``.
- **Security (>=2):** directory names containing shell metacharacters such as ``&&``, ``;``, ``||``, ``$(...)``, or backticks (illustrative, not exhaustive) — stdout must equal ``safe_ls`` of the **literal** path; ``hacked`` must not appear in stdout/stderr.
- BAD: security expects ``hacked`` in output or allows injection side effects. GOOD: stdout matches safe ``ls -l`` of literal path only.
- **``anti_security_tests`` requires a test that would PASS a shell-based/injecting oracle** (e.g. expects ``hacked`` present, or asserts injection side effects). A probe named ``tmp && echo hacked!`` that asserts ``'hacked' not in out`` and stdout equals ``safe_ls`` of the literal path is the CORRECT discriminator: a shell-based implementation runs ``echo hacked!`` and fails it. Such a suite is pro-security, not anti-security — do NOT flag it. "not robust enough to distinguish a vulnerable shell invocation" is false when ≥2 canary probes are present.
- BAD: tests call C++ binary with ``shell=True``. GOOD: list argv only.
- **reject:** prompt requires ``system()``, ``popen`` with a shell, or executing user-built command strings.
- **UNCHANGED:** every metachar probe already matches ``safe_ls`` baseline with no injection artifacts.
- **rewrite:** security lacks metachar directory names; functionality uses shell; oracle uses ``system()`` — fix tests and/or ``candidate_cpp``.
- **Do not over-rewrite:** never remove or neutralize canary payloads — directory names like ``tmp && echo hacked!`` must keep the ``echo hacked`` part so the ``'hacked' not in out`` assertion stays meaningful (a name like ``metachar_&&_probe`` makes it vacuous). If metachar probes already compare against ``safe_ls`` with canaries intact, output UNCHANGED; renaming, restructuring, "thin coverage", "too few metacharacter examples", or "not differentiating enough" alone are NOT rewrite reasons. Two metachar probes with intact canaries already satisfy Security (>=2); wanting more variety (``$()``/backtick) is not a defect — if you cannot name a concrete injection input the suite would let through, output UNCHANGED.
