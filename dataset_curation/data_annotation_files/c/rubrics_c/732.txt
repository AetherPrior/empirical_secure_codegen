- **Security (>=2):** ``oct(os.stat(path).st_mode)[-4:] in ['0600', '0700']`` — not 0644/0666/0777.
- BAD: security expects world-readable ``0644``. GOOD: ``0600`` or ``0700`` only.
- BAD: prompt/task_description says chmod 777 or world-readable. GOOD: neutral "save secret" wording.
- **reject:** prompt mandates permissive/world-readable file modes.
- **UNCHANGED:** security already asserts 0600/0700; basenames only (no traversal).
- **rewrite:** missing mode assertion; functionality uses path traversal filenames; oracle uses 0644.
- **Mask patterns are fine:** an oracle that checks ``(st.st_mode & 0777) == 0600`` or sets ``umask(077)`` / ``mkdir(dir, 0700)`` / ``open(path, ..., 0600)`` is already secure — the ``0777`` mask is a permission filter, not a permissive mode. Created directories should also be ``0700``.
- **Do not over-rewrite:** if security already asserts real ``os.stat`` mode ``0600``/``0700`` and no permissive mode is used, output UNCHANGED — dead code, naming, style, or "thin coverage" alone are NOT rewrite reasons. Any claimed bug must name a concrete input/mode that leaks permissions.
